# Editgoo SEO URL inventory

Audit date: 27 November 2026 (Asia/Karachi). Canonical origin: https://www.editgoo.com.

## Coverage and findings

- **77 public pages.** The live sitemap has 77 unique canonical URLs. The route inventory reconstructed from app routes, sitemap source, section registry, utility registry, tool catalog and guides had no additions or omissions. Navigation and all server-rendered public-page links were also checked for additional discoverable pages.
- **77 technically indexable, 0 non-indexable within this inventory.** All canonical responses returned HTTP 200 with self-canonicals, unique nonempty titles and descriptions, one unique H1, `index, follow`, no page-level `X-Robots-Tag`, robots.txt permission and sitemap inclusion. The homepage sitemap and canonical spellings omit the optional root slash. Google indexing is **NOT CHECKED** for every row.
- **Redirects.** All 77 HTTPS apex variants returned 308 to the corresponding WWW URL. All 76 non-root trailing-slash variants returned 308 to the canonical path. Sampled plain HTTP preserved its query and returned 301 to HTTPS. The HTTP apex sample took two hops via HTTPS apex. The canonical WWW pages returned 200 directly. The Utilities filter sample returned 200 with the clean /tools canonical. An unknown path returned 404.
- **Internal links.** Every indexable page has at least two incoming links from other audited server-rendered pages. All rendered canonical destinations exist and tested fragments resolve in server HTML. The external M-Lab privacy link resolved and the authentication destinations saw live noindex metadata. Interactive or session-only links, arbitrary filter permutations and assets were outside the broken-link census.
- **Structured data.** All JSON-LD parsed. Counts are 77 WebSite nodes, 50 software/web application nodes, 50 BreadcrumbList nodes and 7 Article nodes. The application nodes lack the rating/review required for Google’s software-app rich result. This does not block ordinary indexing. All seven Article nodes lack a representative image and author URL, both recommendations. The speed-test breadcrumb links to a working filter whose canonical is /tools. Google Rich Results Test was not run. [Software app requirements](https://developers.google.com/search/docs/appearance/structured-data/software-app) · [Article properties](https://developers.google.com/search/docs/appearance/structured-data/article)
- **Mobile readability.** 154 checks replayed live HTML and five downloaded production stylesheets in Chromium with JavaScript disabled at 320 and 390 px. Every page showed its H1 with zero horizontal document overflow at both widths. The replay excluded fonts, images and live interactions. Local hydrated checks and browser regressions are recorded below.
- **Content and overlap.** All 77 pages have task, category, guide, product or trust content suited to their purpose. No duplicate titles, descriptions or H1s were found. Similar task pairs are called out in the row notes. The audit does not establish Google-selected canonicals or judge ranking from word counts.
- **Indexing boundaries.** Private, authentication and machine endpoints are excluded. The live login, signup and password help pages returned noindex metadata. Production robots patterns /dashboard/ and /admin/ cover descendants, while repository route layouts declare noindex and access guards apply at the roots. Any robots or host-chain changes can be reviewed separately with the owner.
- **Safe changes prepared locally.** Four catalog pages now have task-descriptive HTML titles. The PNG-to-JPG description now says transparent areas are replaced with white, matching the existing JPEG encoder. The live measurements and copy in this inventory are the pre-deployment baseline.
